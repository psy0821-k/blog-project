# 기술 스택 선택 이유

본 문서는 프로젝트에서 어떤 기술을 사용했는지, 그리고 왜 사용했는지를 정리한 문서이다.

## 주요 기술 선택

### Next.js

- SSR을 활용하여 초기 HTML을 빠르게 제공하고, SEO와 웹 접근성을 고려했다.
- 인터랙션 중심의 기능은 CSR이 적합할 수 있지만, 블로그의 주 목적이 콘텐츠 제공에 있다는 점을 고려해 Next.js를 선택했다. 또한 인터랙션이 필요한 영역은 Client Component로 분리하여 구현할 수 있다는 점도 선택의 이유였다.

### Prisma

SQL 문법과 타입 불일치 문제를 해결하기 위해 도입했다. 데이터베이스는 PostgreSQL을 사용한다.

- **타입 안정성**: 데이터베이스 구조 변경 시 TypeScript 타입이 자동 생성된다.
- **자동완성**: 에디터에서 데이터베이스 필드명을 기억할 필요 없이 자동완성 기능을 제공한다.
- **선언적 스키마**: `schema.prisma` 파일에 데이터 구조를 정의하면 마이그레이션부터 클라이언트 생성까지 한 번에 해결된다.

### TanStack Query

페이지네이션, 필터링과 같이 클라이언트에서 반복적으로 서버 데이터를 조회하는 상황에서 캐싱과 리페칭을 관리하기 위해 사용한다.
또한 댓글 기능처럼 사용자 액션에 즉각적인 반응이 필요한 곳에서는 낙관적 업데이트(Optimistic Update)를 적용해 실제 서버 응답을 기다리지 않고도 UI가 먼저 갱신되도록 구현할 예정이다.

### Tailwind CSS

클래스명을 따로 짓지 않고 유틸리티 클래스로 빠르게 스타일을 적용할 수 있다는 점에서 선택했다.
기본 유틸리티 클래스만으로 부족한 프로젝트 고유의 일관성은 토큰을 통해 보완한다.

### ESLint & Prettier

코드 구조를 동일하게 맞춤으로써 유지보수성 및 가독성을 높일 수 있다고 생각했다.
명시적으로 코드를 작성하는 것도 중요하지만, 세미콜론은 자동으로 붙여주는 ASI(Automatic Semicolon Insertion) 덕분에 이번 프로젝트에서는 세미콜론 사용을 제외하기로 했다.

추가로 린트 도구와는 무관하지만, 가독성을 위해 코드가 200줄 이상일 경우 파일을 분리한다는 규칙을 함께 적용할 예정이다.

### Zod

회원가입, 로그인, 댓글 기능 등에서 사용자가 보낸 값을 검증하기 위해 사용한다. 이를 통해 좀 더 가독성 좋은 코드로 검증 로직을 명확히 드러낼 수 있다.

### Sharp

이미지를 저장할 때 PNG보다 WebP로 저장하면 더 빠르게 불러올 수 있다.
파일 확장자마다 감소하는 크기는 다르지만, 이를 통해 네트워크 전송량과 로딩 시간을 단축할 수 있다.

### Playwright & Vitest

AI를 활용한 테스트 주도 개발(TDD)을 적용하고 테스트를 자동화하기 위해 사용한다.
단순히 눈으로 확인하는 방식으로는 실패 케이스가 누락될 수 있다고 판단했다. AI를 테스트 작성에 적용하면 더 효율적이고 안전한 서비스를 만들 수 있을 것이라는 기대에서 도입하게 되었다.
